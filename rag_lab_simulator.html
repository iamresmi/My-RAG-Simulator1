4. Rerank candidates

A reranker scores the retrieved candidates against the query, then sorts them. It cannot recover a relevant chunk that initial retrieval never found.

Run retrieval first, then rerank.
In real systems, a cross-encoder can read the query and each candidate passage together. This simulator uses a simple scoring heuristic so you can inspect how ranking changes.

5. Select context for the LLM

Choose how many of the best-ranked chunks should be passed to the model. More context can help—but can also add noise, cost, and contradictions.

3
Select chunks after retrieval/reranking.
In production, context selection also considers token limits, diversity, source trust, recency, and whether multiple chunks are needed to answer the whole question.

6. Generate an answer

The LLM receives the query plus retrieved context. This demo uses a simple extractive rule-based answer—not a live LLM—so the behavior is inspectable and repeatable.
